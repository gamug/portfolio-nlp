| **FR-018** | The production pipeline's model selection (name, commit SHA, and batch size for each of the four ML stages) is schema-validated (`pipeline_config.PipelineModelsConfig`, `extra="forbid"`) and lives in one git-tracked file, `config/pipeline_models.json`, loaded by `pipeline.py` at import time — not a Python literal constant and not runtime-overridable via any CLI flag or env var. A format change only, not a relaxation of constitution AI #1 ("model selection is pinned, not dynamic"): changing a model still means editing this file in a reviewed PR. `sentiment` has no `batch_size` (its batch size is hardcoded to 1). | `pipeline.py` exposes the model, revision and batch-size constants as real, monkeypatchable module attributes whose values match `config/pipeline_models.json` (regression-tested); an unknown key, a missing stage, or a non-positive `batch_size` in the JSON fails `PipelineModelsConfig` validation with pydantic's own message; a malformed `config/pipeline_models.json` fails on `import pipeline` itself rather than silently degrading; no CLI flag or env var can point the pipeline at a different config file. The other pins (scope, attribution, sector, sentiment pair model) are in their own `config/*.json`; the category step reads the `category` pin of this file. |
